# v4 UE 基础资源程序版

本次在既有 AetherLab 上增量实现。人物采用 UE 5.8 官方 Manny，行走与攻击采用官方模板动画；场景与装备采用 Engine/BasicShapes。旧 SwordMagic 资产与旧启动入口保留，新模式不依赖 Blender 模型。

## 启动

- 工程：`C:/ueproject/test/AetherLab.uproject`
- 新入口：`Scripts/PlayFrontier.ps1`，默认本地档案 LocalPlayer。
- 主机：`Scripts/PlayFrontier.ps1 -Listen -Profile Alpha`。
- 客户端：`Scripts/PlayFrontier.ps1 -Connect 127.0.0.1:7777 -Profile Beta`。
- 相同 Profile 重连恢复背包、装备实例、任务、技能学习和领奖记录；重新进入时出生在已绑定的旅舍或最初出生点。
- `DevProfile` 仅为本地开发身份，不是账号登录或正式身份认证。每个档案只允许一个在线连接。

## 操作

WASD / 鼠标移动视角，Shift 冲刺，Ctrl 跳跃，Space 闪避；左键轻击、按住超过 0.35 秒后松开重击，右键格挡。1–4 选择元素，F 施法；E 交互，Q 药剂，R 循环主手，T 装卸盾，G 搬起/放下，V 推物。I 背包、J 任务、K 技能、M 地图、P 队伍、Esc 菜单。背包面板内 B 拆分第一个可拆堆叠、N 合并同类堆叠。F5 保存世界。菜单不会暂停在线服务器。

本阶段 F 暂用于施法，尚未实现设计稿中的 F 锁定以及可重映射 Enhanced Input；界面为 C++ Canvas 功能界面，尚未迁移为 UMG ViewModel。

## 可玩路线

山径拾取两份补给 → 南门交互 → 城镇登记和绑定旅舍 → 导师学习引焰/引泉并授予装备 → 木桩三次攻击、格挡训练敌人、熄灭自己的训练火 → 自由顺序完成林地三火点/救援和水工坊复流 → 回导师学习霜/电 → 旅舍招募同行者 → 北侧修道院启动遭遇 → 击败守卫取得古印 → 回镇交付。主线完成后开放补给日常和东北中继防守。

世界按约 800×800 米搭建，采用基础几何体和道路连接；不是经过内容制作和性能验收的开放世界成品。水工坊可从维修旁路、切/烧绳落桥、冻结水面三条路线抵达机械泵；放置铁杆连接固定电源与接收器提供另一个供能交互。供水检查当前世界事实，个人进度单独结算。

## 代码与职责

- `AetherProgression.*`：个人档案、物品实例、堆叠/拆合、32 格容量、拥有权与双手占用、任务前置、领奖去重。角色档案仅复制给拥有者。
- `AetherFrontierCharacter.cpp`：PlayerState 持有 GAS ASC/Attributes，Pawn 作为 Avatar；权威交互、物理手柄搬运、药剂、装备事务、AI 同行与救援。
- `AetherFrontierWorld.cpp`：场景装配、档案存储、世界快照、公共事实和遭遇参与记录。
- `AetherFrontierInteraction.cpp`：灰盒 NPC、供水、教学、商店、日常、主线入口。
- `AetherFrontierHUD.cpp`：资源、背包、主线、能力、地图、队伍及 UE 内端到端 smoke。
- `ReactiveCore`：固定步热/水/相变；雨只增加热学水量，不增加电学湿润；电使用独立接触关系、路径长度衰减和统一能量账本。
- `ReactiveRuntime`：权威运行、碰撞接触窄相检查、状态复制及存档适配。特效不是规则来源。

## 保存及网络边界

资产事务先写新一代 SaveGame，再发布内存与复制状态。保存使用两个交替世代，读档选择有效的较新世代。失败不会先更新金币或背包。个人领奖记录与奖励同一档案提交；公共世界改变与个人领奖分开，供水等交互可检查既有结果并重试。

存档位于 `Saved/SaveGames/AetherFrontier_v4{0,1}.sav`，与旧 v2 存档隔离。世界定期保存热学质量/焓、燃料、结构状态、允许对象的位置及供水/电源事实。桥梁恢复使用作者预设的落下位置；搬运租约不保存，重启时释放。没有承诺逐帧物理重放或跨进程数据库事务。

旧装备组件的直接 RPC 在个人档案管理模式下被禁用，必须走个人档案事务。搬运有距离、质量、碰撞、单持有人和断开释放检查。最多四个真人/AI 总席位是原型限制。

## 尚未达到完整设计稿验收的部分

- 当前是本地持久化与开发身份；正式账号服务、数据库/WAL 级故障恢复、服务端独立发布包未完成。
- 尚未实现 World Partition 流送和区域休眠、完整 GAS Ability 化近战/救援、可重映射 Enhanced Input、UMG MVVM。
- 首版八步主线为压缩灰盒流程，不代表 60–90 分钟内容已验收；任务定义仍有代码配置，尚未全部转为内容资产。
- 日常仅补给交付模板，公共活动与 Boss 为简化遭遇；巡逻/灭火日常、公共活动完整状态机及 Boss 多阶段仍需补齐。
- 同行者为简易避障/跟随/战斗/治疗/救援，没有 StateTree、动态导航危险代价、受管理多人副本排队和完整队伍邀请 UI。
- 电传播已有按质量/长度分配和预算损失策略；复杂 Receiver 合并/容量标定、不同网格分辨率等价性、落物伤害统一窗口、完整铰链结构图及 50 项 RX 验收尚未完成。
- 官方模板动画用于占位，尚未制作剑盾/双手锤/法杖完整动作层、手部 IK 和正式战斗蒙太奇。

## 验证入口

`Scripts/Build.ps1`、`Scripts/Test.ps1`、`Scripts/SmokeFrontier.ps1`、`Scripts/TestFrontierNetwork.ps1`。网络脚本启动独立 Editor 服务进程和两个并发客户端，再重启服务进程并用相同身份重连。它不是打包 Dedicated Server 的验收。

最终实测结果写入 `Docs/Verification-v4.json`。Smoke 中部分训练目标由服务器测试夹具推进；实际灭火事件、奖励持久化、物理断绳和人物资产使用真实 UE 运行结果。自动测试通过不能替代手工游玩与四人延迟/丢包测试。

## 本轮实测结果

UE 5.8.0，CL 55116800：编辑器目标编译通过；26 项自动测试通过（0 失败）；27 项新灰盒运行检查通过，包括真实灭火、落桥、移动导体通电/断源、档案写失败不发布和世界快照恢复；2 个并发客户端、服务进程重启后同身份重连通过。旧装备和反应实验台回归也通过。实际渲染截图已检查，分辨率 1600×1000。

默认打开工程点击 Play 即运行新灰盒；旧实验台 smoke 脚本已显式指定旧 GameMode。

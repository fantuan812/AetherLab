# v7 反应引擎与机械交互

基于 Design-v4.zh-CN.md 第 14.11、14.17、14.23 节推进。仍使用 UE 官方人物和基础几何体；这是本批实现与有限验证记录，不是全部设计验收。

## 液体转移

- 水桶改用服务端原子转移：先验证来源、目标容量、液态比例、视线和个人作用权限，再同次扣增。目标满、冻结或被遮挡时不扣来源水。
- 转移携带来源温度对应的比焓，不能将热水重新当成环境温度的水。只抽取液态部分，冰的潜热仍留在状态模型中。
- 水桶对火点最多转移目标可容纳的水；其余保留在桶中。检查已清理火点不继续耗水，实际灭火反应仍归属操作者并推进任务。
- 热学水与电学水按均匀混合比例转移、抽取和蒸发。雨水不能通过普通容器转移凭空变成有电连接资格的水；雨水本身不增加电学湿润。
- 增加转移水量/携带焓、抽离水量/携带焓的累计账本，F10 可查看。转移是内部交换；水井向角色水囊抽取是离开材料模型的边界。水囊仍按现有环境温度施法策略工作，尚未实现完整水囊温度/相态持久化，不能声称背包内外封闭守恒。

## 切割与结构

- 独立 CuttingWorkJ 输入与装备命中字段，材料新增 CutResistanceJ。单位为焦耳；0 表示不可切割。切割消耗结构完整度，不伪造冲量或热量。
- 冲量仍使用 ImpulseNs 和原有抗冲击参数。取消按 TrainingSword 字符串特判直接注入 40 N·s 的割绳逻辑。
- 基础训练剑数据资产：轻击 24 J，重击 40 J；绳索抗切割功 20 J。其他武器默认切割功 0。参数是当前灰盒标定，并非真实材料常数。
- 反应系统统一发布断裂，已有支撑组件释放桥梁刚体；不由任务状态直接放桥。重复输入仍由来源与 InputId 去重。
- 切割账本记录送达、吸收和未使用的功，三者可核对；未使用功不转换成额外伤害、热量或冲量。

## 有时限的机械归属

推、投、放下、受到物理冲量和支撑断裂建立短期来源。默认 5 秒，可配置 0–30 秒。到期自然碰撞仍有物理后果，但不永久记在曾经操作过的玩家身上。结构恢复不重新赋予旧操作者归属。

碰撞伤害目前仍是冲量/质量的动能近似及去重窗口；相对接近速度和持续挤压的独立模型尚未补齐，不把此轮归属修复等同于完整碰撞验收。

## 存档

新物理记录写入材料签名 schema 1，包含抗切割参数；旧记录缺少此字段时按 schema 0 验证原签名，保存后升级。未知 schema 或不匹配的材料签名整批拒绝，保留原有原子恢复方式。

## 轻量验证

- UE 5.8 编辑器目标增量编译通过。
- Scripts/TestReactionLight.ps1：8/8 规则测试通过，测试逻辑约 0.066 秒。覆盖容量限制、携带焓、半冻结液体、雨电比例、蒸发、抽取账本、切割去重与无效输入的原子拒绝。
- Scripts/CheckReactions.ps1：隔离存档、约 3 秒游戏时间、无渲染短检查。包含 14 项基础场景检查；指定本机旧测试档 -LegacyFixture AetherV5Check_20260918a0 后另检查旧 schema 和实际恢复，本次合计 16/16 通过。旧档只读，不提交测试存档。
- 真实流程验证：有限水桶→灭火事件→个人任务事实；训练剑配置→无冲量切割→绳索断裂→桥梁进入 Chaos 模拟；归属到期；新快照恢复与旧存档兼容。
- 资源更新脚本 Scripts/UpdateReactionAssets.py 只保存基础训练剑资产，未批量重建模型或地图。

没有运行多人、长时循环、压力测试、全量 Cook/HLOD 或渲染验收。分类型接触的稳定阈值、显式液体拓扑、冻融警示、桥梁落稳后导航连接和完整 RX 验收仍待后续工作。详细结果见 Verification-v7.json。

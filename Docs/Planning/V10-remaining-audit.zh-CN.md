## 核心证据

- AetherLab.uproject 的插件列表没有 CommonUI；Source/AetherUI 目前仍从 UAetherFrontierPanel 进入兼容页面。
- 审计开始时，AetherSQLite::Open 的调用者仅为存储实现、测试和离线迁移 Commandlet；没有生产游戏启动调用。
- 审计开始时，FAetherProfileCoordinator 的实例位于测试，生产 AAetherPlayerController 没有 v10 命令 RPC。
- AAetherFrontierMode::Commit 仍 DuplicateObject 旧 UAetherFrontierSave、WriteDatabase，然后发布 PS->Profile。
- UAetherSkillTreePage::SetLegacySource 使用 FromLegacyMask；ApplyCommandAvailability 在生产原生通道未绑定时禁用成长动作。
- 新资产制作脚本只写入了制作流程，没有执行；不能把脚本文件计为生成后的 uasset。
- MotionBricks 独立 CPU 证据不等于 UE 插件、调度、重定向或 Vulkan 已实现。

## 此次审计发现并修复的代码缺陷

详情会话曾将随机确认令牌直接写入 CommandId。现有 AetherCommands::Validate 要求 CommandId 高 64 位等于 ExpectedProfileRevision+1，因此正常新请求会被编码器拒绝。现改为调用统一 NewCommandId，弹窗令牌仍只负责 UI 失效保护；成功派发后保存固定命令字节供重试。该修复仅经过源代码对照，未编译、未测试。

## 接下来实施的依赖顺序

1. 连接到协调者的运行时通道：有界 RPC、连接绑定、限流、会话/Pawn 复验、拥有者分片快照与固定字节重试。
2. 存储/场景启动及唯一写者切换，再让 UI 的成长与库存动作走真实生产通道。不能让旧 SaveGame 与 SQLite 同时成为同一角色的可写权威。
3. 补齐资源效果、装备、任务/NPC 适配以及正式背包/容器/CommonUI/其余页面。
4. 原生动作插件、调度、动画与作者资产。
5. 全部实现及必要资产具备后，按用户顺序统一编译、轻量验证与修复；验证失败不能改成“通过”。

本审计不缩减方案范围。每个后续提交应更新对应实际进度；“尚未接通”不得通过标签改写为完成。

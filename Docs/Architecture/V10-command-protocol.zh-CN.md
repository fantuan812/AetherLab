# v10 命令协议

AetherCore 的 FAetherPlayerCommand 使用有限 EAetherCommandType，覆盖库存、装备、容器、技能、交互和领奖动作。每种动作只接受自己的字段；无关字段、超量数量、未知操作、无效 ID 和版本均拒绝。装备显式指定 SlotId；拆分可指定目标格，-1 表示由服务器选择空格；容器转移方向属于请求本身。

ActorIdentity 不在客户端信封内。服务器仍必须从连接绑定身份，重新验证所属权、距离、条件和实际规则，不能把协议校验等同于权限校验。交互 Offer 接口只有 const 查询；Offer.Available 不构成执行权限。

ProtocolVersion=1 与 SaveSchemaVersion=10、内容 schema、模型 revision 分开。命令 GUID 延续事务契约：高 64 位绑定 ExpectedProfileRevision+1，低 64 位随机。重试保存相同 ID 和完整编码字节，修改目标/数量必须创建新命令。涉及世界聚合的动作必须携带期望世界版本。

请求编码采用显式小端整数、有界 ASCII 定义 ID 和固定字段顺序，上限 1024 字节，不使用反射内存布局或 FName 索引。解码不接受尾随字节，错误时不发布部分命令。标准结果携带最终版本、实际数量、实例 GUID、受影响定义 ID 和有界原因参数；原因支持中文 UTF-8，字典键排序后编码。失败结果不能宣称转移了物品。

后续已实现完整角色 DTO、17 类角色候选及异步 SQLite 协调器，仍未替换旧 RPC 和游戏保存入口。请求协议保持 1；标准回执格式现为 2，并兼容读取格式 1，详见 [容器与转移回执](V10-container-transfers.zh-CN.md)。V10-03 仍为 in_progress。

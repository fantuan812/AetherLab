# v10 技能身份与等级效果

此阶段完成施法运行时的身份拆分与等级参数接入；尚未完成技能成长事务、图形技能树、快捷栏存档或整档迁移。

## 唯一身份

- Core 中的 Skills.json 定义稳定 SkillId、有限机制、三级参数、学习成本、故事任务门槛与有向前置关系。
- AetherLab 模块启动时注册 Aether.Skill.<SkillId> 原生标签。服务器与客户端使用同一规范数据；该目录已有 NonUFS 打包配置。
- 共享 UAetherSpellAbility 的每个 Spec 通过原生复制的 DynamicSpecSourceTags 标识身份；Level 只表示等级。旧数字快捷键仅在入口映射 SkillId。
- 不按 InputID、Level 或同类第一个 Spec 查找法术。无身份、多重身份、重复身份或未知等级不能正常激活。
- PlayerState ASC 再次授权时复用 Handle 与等级；不因重生重复授权或重置已升级的等级。旧进程中的 tagless Spec 不静默猜测迁移，需正常重启新版本。

## 实际施法

CheckCost、ApplyCost、ActivateAbility、目标扫描和物理注入共同读取同一等级表。火球热量、抽热量、电刺激量、水转移量、法力成本、射程和冷却均来自当前 Rank。四种 rank 1 保持旧玩法数值。

水技能先确认有限储水量，只有反应系统接受注入才扣水；失败退还本次已扣法力且不设置冷却。数值升级不能绕开服务器身份、目标、材料、距离和资源检查。

旧 HUD 的数字技能费用查询仍是 rank 1 兼容显示；正式等级详情与升级入口要在 V10-11/12 后续替换，因此目前不向玩家开放等级修改入口。

## 数据与存档边界

v9 反射档案完全保留，其四位 LearnedSpells 仍控制旧任务流程。LegacyBit 只用于这一过渡映射，不能作为新持久技能模型或等级。新技能定义中的任务引用尚未接入统一内容引用检查，图标也还只是逻辑 ID。

后续仍需永久/故事/装备/临时来源、实际点数事件账本、学习/升级/级联重置、显式技能 DTO、Profile 原子提交及 UI 接入。不得把这一提交当作完整 V10-11 验收。

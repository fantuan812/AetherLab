# v10 统一详情（代码实现，未编译、未测试）

本单元推进 V10-09，仍为 in_progress。只人工审阅源代码；遵照用户要求，没有执行编译、规则测试、启动检查或资产制作。不能把已有菜单或库存的历史通过记录当作本单元验收。

## 身份与数据

AetherCore/Inspection 定义 ItemInstance、ItemDefinition、EquipmentSlot、SkillNode、StatusEffect 五种查看对象。展示上下文包含拥有者、会话代数和展示快照版本。数据库 Profile/World 版本另存，不能把 UI 展示代数误填入持久命令。

输入必须来自已经过授权的拥有者快照；这些值对象本身不提供网络认证，也不能作为服务器信任客户端的依据。换 Pawn/重连必须使用新的 SessionId，所有影响详情的定义、资源、状态变更必须推进 SnapshotRevision。

打开装备槽时固定当时的实例 GUID，不能只保留槽名。刷新时若身份或版本变化，显示“对象已变化”并移除动作，不自动定位到合并后的对象或同一格的新物品。纯定义详情没有实例动作。

## 共享规则

装备比较在库存副本上调用原生 Equip 和 EquippedStats；包含双手武器卸下副手、绑定限制、耐久折减与被替换实例。戒指等多槽物品要求明确选择 ComparisonSlot。数值是已支持的装备附加总值，不冒充尚未接入的战斗最终伤害；未定义属性不显示虚假零值。

新增 CanLearnNext 只读查询，实际 LearnNext 与详情共用学习条件。当前/下级/所选节点效果直接使用技能定义的等级解析值，区分永久授权、装备/临时授权、故事授予与付费成长。定位前置和追踪任务是本地导航意图，不会产生学习命令。

状态效果使用实例身份、来源和可选结束时间；无结束时间明确显示无固定时限。剩余时间由同步服务器时间计算，不依赖本地随意倒计时。

## 三层展示与命令

FAetherInspectionSession 分开管理悬停、持续详情、数量/危险确认。悬停模型去掉动作；Back 先退确认再退详情。确认令牌只用于匹配一次性 UI 回调；真实命令 ID 由 AetherTransactions::NewCommandId 按当前档案版本创建。回调必须匹配当前令牌和快照，数量限制取重新构建后的模型。

装备、卸下、丢弃、锁定、收藏、学习/升级、快捷位生成已有 FAetherPlayerCommand，并经同一协议编码器验证。快捷位使用 Hotbar.1..4。没有新的直接修改库存或调用角色行为的旁路。丢弃必须具有世界版本；出售/维修依赖商人报价，用药依赖资源屏障，未具备快照时没有伪造可执行按钮。

发出请求后会话保留固定命令与字节供统一服务重试，并禁止再次操作。存储不可用/忙碌保留待确认状态；成功回执先于拥有者快照时，必须等同一拥有者会话达到提交版本才解除等待。关闭详情不删除待确认命令；拥有者退出前由命令服务接管未决请求，不能直接丢弃重试身份。

## 可复用界面代码

AetherUI/Inspection 提供滚动详情卡、带固定请求身份的动作按钮、独立数量确认控件。比较同时显示前值、后值、带符号差值与辅助颜色；当前/下一级技能参数分块显示。图标解析回调带展示代数，旧资源不能覆盖新对象。卡片内部右键只由 UI 消费。没有每帧拼接正文。

宿主负责使用统一逻辑坐标调用 PlacePopup，并在窗口缩放时重新布局、约束卡片尺寸；负责把确认控件放到模态层并使用菜单令牌。控件只发意图，最终操作仍须经过会话复验和统一命令服务。

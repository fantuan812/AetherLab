# v10 整档原子导入存储入口

ImportLegacy 是离线/启动迁移入口，不能从玩家 RPC 调用。调用前必须先完成旧 reader、来源校验、所有领域 DTO 转换和整档不变量检查；世界转换和离线工具现已接通，见 [完整离线导入](V10-world-dto-import.zh-CN.md)；游戏入口切换仍未完成。

## 与普通命令的区别

普通命令需要准确匹配当前版本并推进一次；迁移必须保留旧角色和世界的既有版本。不能把导入拆成多个普通命令，也不能为满足首次写入规则而归零旧 Revision。

输入最多 128 个角色和一个完整世界聚合，每行最多 4 MiB，合计最多 32 MiB，同时最多一份导入负载在写队列内。输入全为值对象，后台不持有 UObject。

## 原子边界

在同一个 BEGIN IMMEDIATE / COMMIT 中：

1. 检查固定的 Migration/LegacyV9 标识。
2. 没有标识时，要求 aggregates、receipts 和 effects 全为空。
3. 按原版本写入全部聚合，不执行 UPSERT，不覆盖已有行。
4. 写入绑定来源 schema/SHA256 和转换结果 BLAKE3 的标识，再提交。

Migration 是新增的保留聚合种类，标识负载单独版本 1。SQLite 表结构和 user_version 10 不变；普通玩家事务不能写此种类。

重复同一内容返回 Replayed；快照数组的顺序不影响摘要。相同来源哈希却换转换后内容、另一份旧档、无标识但已有游戏数据，均拒绝。导入后游戏推进了角色版本，再次导入不会回退状态；若发现原本应有的聚合缺失、版本倒退或同版本内容被改写，返回损坏诊断，不伪报完成。

任何 COMMIT 前失败都同时回滚聚合与标识；COMMIT 后响应丢失依靠标识去重。原始 .sav 的只读备份与来源校验仍由迁移工具负责，此存储接口不处理文件，也不会删除旧档。

# v10 固定格与装备值规则

当前实现位于 AetherCore/Inventory，独立于冻结的 v9 profile。它是可验证的值规则和定义表，尚未接入游戏 RPC、数据库 DTO、GAS、真实战斗磨损、商店扣款、外观或图形背包。以下通过的是规则验收，不是 V10-06/07 的完整游戏验收。

## 状态与定义

Content/AetherCore/Definitions/V10/Items.json 是新物品规则源，ContentSchemaVersion=3，默认 32 格。包含全部 15 个基线物品 ID，以及头/胸/手/腿/足/项链/双戒指所需的新定义。装备槽固定为十个，类别许可、AllowedSlots 和额外占位由数据声明。新装备的获取入口和表现资源仍待接入，IconId 目前是展示目录键，尚不能据此声称图标资源已验收。

武器的动作基础值由 EquipmentId 引用配置负责；新 Stats 仅表示装备附加值。Wear/Repair 只计算候选实例耐久，EquippedStats 只返回纯计算的附加值；必须由后续适配器执行真实结算，修理扣款必须与耐久一起提交。

实例保存 GUID、真实 SlotIndex、数量、品质、词条、绑定、任务实例、状态组、耐久、锁定与收藏。StackKey 比较所有会被合并洗掉的状态；格子位置和 GUID 不属于堆叠键。收藏与锁定独立，锁定阻止误售/误丢，绑定与任务限制独立检查。

## 操作边界

- 容量来自有效定义，UI 不能提交自造容量。空格是未占用的真实索引，过滤 ViewIndex 不参与规则。
- 所有变更先验证输入，再操作副本，最后验证全部不变量并一次替换。此替换是内存值提交，仍需数据库协调者发布。
- 移动保留 ID，交换要求显式动作；拆分复制全部状态并生成新 ID；部分合并报告实际数量，目标保留 ID，耗尽的源删除。
- 整理按定义/品质/稳定 GUID 排序，可选择合并；被消耗的源 ID 不会重新作为目标复活。
- 装备只引用库存实例。满包也能卸装；戒指可选 Ring1/Ring2，同一实例不能占两个引用。
- 双手武器装备时原子解除副手引用；向被双手占用的副手直接装备盾被拒绝。
- 耐久关闭时用 -1，不产生假磨损；启用时磨损饱和到 0，损坏倍率影响纯属性计算。修复只恢复候选耐久，不虚构扣款成功。
- 命令协议追加 SetItemFavorite=22；SortInventory.Enabled 明确表示是否合并。所有操作仍待通过权威 Gateway 接入实际玩法。

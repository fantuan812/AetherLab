# v10 角色命令候选与异步事务协调

## 已实现边界

AetherGameplay 的 FAetherProfileCoordinator 在游戏线程持有会话和在途命令，以有界 Future 轮询调度 SQLite；它不持有 Actor/UObject，不在游戏线程等待磁盘。当前为可接入运行时的服务及实际数据库测试，尚未替换旧 PlayerController/RPC、复制快照或游戏保存入口。

已支持 17 个命令：九种库存编辑、四种技能操作，以及购买、出售、维修、待领奖励领取。经济规则详见 [经济事务](V10-economy-transactions.zh-CN.md)。其余世界/治疗命令返回 UnsupportedAction，不提交空成功。

## 执行顺序与回执

Submit 复核服务端建立的 SessionId/PawnEpoch、协议和载荷形状。每个角色最多一个在途命令（包括旧断线会话），每个协调者最多 16 个会话/任务。RPC 的连接鉴权与请求速率限制仍需在接入层实施；BeginSession 不是网络认证接口。

依次执行：持久回执查询 → 读取当前角色 → 核对数据库行/DTO 版本和角色 ID → 当前服务器状态上下文 → 计算完整候选 → 单一 SQLite 事务 → 重读已提交快照 → 发布资格检查。Poll 仅处理已就绪 Future，返回结果前不阻塞等数据库。

LookupReceipt 按角色+命令 ID 查询并比较完整协议/请求字节；同 ID 不同内容冲突。查询 Missing 不代表许可，Commit 仍在同一 BEGIN IMMEDIATE 内复验回执和所有聚合版本。成功重试在领域计算前回放原结果，不会因物品已移动、原堆已减少或技能已升级而误判失败。

技能前置任务集合从已提交 Profile.Claims 重建，不能依赖上下文的旧任务集合；现场战斗/服务状态在发起提交前由服务器重新解析。Hotbar.1–4 映射内部 0–3。LearnSkill 不静默变成升级。未变化但合法的成功操作仍提交一个版本化回执，后续重试保持幂等。

## 生命周期

BeginSession 同角色重连会替换会话身份；旧会话的 EndSession 无权结束新会话。ReplacePawn 推进 epoch。提交前身份失效会取消未发出的变更；已进入存储队列的提交不能撤销，等待结束但禁止给新 Pawn 发布旧结果。新会话可凭同一命令取回持久结果。

完成结果包含原 token、原回执最终版本及最新持久 Snapshot。回放时 Snapshot 版本允许高于原回执版本，绝不据原回执把当前数据倒退。bMayPublish 仅表示 Poll 当时仍有效；消费者应用前必须再次 IsCurrent(Session)。写失败或响应丢失不发布内存候选。

协调者析构只丢弃自己的 Future，不关闭共享存储；后台任务只持有值对象。外层在世界关闭时排空并关闭存储。一次性效果的幂等投递、ASC/装备表现重建仍需运行时接入。

## 验证

实际 SQLite 用例覆盖拆分完整候选、在途限流、重复回放不重新评估、不同载荷冲突、旧版本同步、首行写失败回滚、升级提交后响应丢失与同 ID 恢复、技能点/等级单次原子改变、旧连接拒绝、旧 logout、提交前断线取消与提交后换 Pawn 不发布。此外拒绝伪造任务上下文及数据库行版本/DTO 版本不一致。

实际结果：UE 5.8 Editor Win64 Development 增量编译通过；44 项规则全部通过（Rules-2718dd121128445a9d6731bd755287fc）。回执查询重构后，普通事务五进程强退恢复重新通过（V10Crash/f70b208c398845509c140efaebe0e158），退出码依次为 0/91/0/92/0。未对个人存档或正式游戏后端执行变更。

后续修正：数据库提交失败或会话/Pawn 已失效时，协调者清除候选数量、受影响对象、转移关系及未确认的世界版本，旧 epoch 不回报候选角色版本。结果本身通过标准回执编码验证。Editor 增量编译与 49 项规则回归通过（Rules-b121aa1e8aef4ff3b2b6f350f89485be）。

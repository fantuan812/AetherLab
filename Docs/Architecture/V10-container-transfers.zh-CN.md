# v10 容器 DTO、实例转移与回执关系

## 当前范围

实现独立容量容器、个人归属、掉落墓碑、完整实例跨容器值规则及持久转移回执。已用真实 SQLite 验证 Profile+World+Container 三聚合并发领取和恢复。当前还没有通用容器命令处理器、场景拾取/落点恢复或两栏 UI，不能把存储用例视为在线拾取验收。

## 容器

FAetherContainerStateV10 支持 SharedChest、PersonalStorage、WorldDrop，保存稳定 ID、版本、归属角色、区域、持久位置和完整实例格网。容量 1–256，与玩家固定背包容量分开；容器没有装备引用。

个人仓储只允许匹配的服务器角色身份。共享箱子和共享掉落不保存个人 owner；绑定物只能处于相应角色的个人仓储，不能借用其他人的 ContainerId。已领空掉落保留非活动墓碑和领取版本；普通空箱子继续活动，空活动掉落被拒绝。

ACNT schema 1 使用有界小端格式、无损 UTF-8 与嵌套库存 DTO，最大 2 MiB+1024 字节。容量和负载长度在分配前校验；未知版本、截断、尾随、非有限坐标和非法归属失败，保留调用方输出。

## 跨容器值规则

TransferTo 接收两个已经过上层授权的容器值；不负责连接、距离、区域就绪、危险物件可收纳策略或掉落权限。装备中的实例禁止搬移，两侧已有重复实例 ID 则拒绝。角色固定容量仍由完整 Profile.Validate 复验；容器容量由容器 DTO 复验。

整堆移入空格优先保留原 GUID 和全部状态。部分转移复制完整 StackKey 后分配两侧均不存在的新 GUID，并返回 From/To/Quantity。目标已有堆仅在完整状态一致且未装备时可以接收；满包时可选择部分数量转移，剩余数量保留在原实例。不允许部分转移时，两侧任一容量失败都保持原值。

值层成功后，上层必须在单一数据库事务中提交来源、目标和相关世界版本；不能分别保存。领取竞争由全部聚合的期望版本决定，不能依赖 UI 禁用或单进程内存判断。

## 回执格式 2

请求 ProtocolVersion 仍为 1，回执格式独立升级为 2；解码继续支持既有格式 1。格式 2 增加明确的实例转移关系，受影响 GUID 和转移关系各最多 512，编码整体仍最多 16384 字节，单条转移数量 1–1000。

一次领奖可发多个堆，ActualQuantity 总数上限为 1000000，不再误用单次物品请求的 1000 上限；格式 1 仍按原 1000 上限解码。整理合并后的源实例即使消失，也在 AffectedIds/Transfers 中保留关系。记录只是提交结果，不能当成新的可执行操作。

失败候选统一清零实际转移数、受影响实例与关系，并保留当前已提交版本，避免多品类奖励只装下一部分后把失败回执误报成部分成功。

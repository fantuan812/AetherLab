# v10 技能成长候选状态

技能状态位于 AetherCore，独立于 UObject/GAS/Widget。此阶段提供经过验证的候选值规则；尚未接入正式 Profile 事务、普通玩家点数奖励、重置 NPC 或技能树，因此不能据此宣称玩家成长闭环完成。

## 来源与授权

LearnedRanks 保存永久自由学习；StoryGrants 保存不可退还的基础 rank 1 及故事事件 ID。装备/临时授予是独立的服务器上下文，不混入持久学习档案。有效等级为所有来源的最高等级，不能相加。卸装/过期只改变其来源，保留永久技能；暂时失去授权的快捷位保留 SkillId，显示层应禁用它，重新授权后可恢复。

基础故事能力免费，不能依赖需自由点数的前置；学习高级节点要求永久前置、任务、角色等级和足够点数。装备临时提供的等级不能用来绕过永久学习前置。

## 点数与退款

PointEvents 保存唯一奖励事件及实际授予额，重复来源不重复发放，修改同一来源金额返回冲突。AvailableSkillPoints 必须精确等于累计来源减去所有在学等级的实付记录。事件最多 4096 条、终身累计上限 100 万点；超过容量拒绝，不能驱逐旧事件后重放领奖。

Purchases 按 SkillId/Rank 保存实付金额及命令 GUID。配置涨价或降价不重写历史支付。重置从候选副本撤回选定自由学习及失去前置的后继，退款实付总额，保留故事基础和仍合法的同级分支。装备授予不会被重置误删。

重置需要权威服务上下文，战斗中、施法中或冷却中拒绝。上下文由服务器实际场景生成，不接受客户端声明。现有方法只提供候选规则，不能单独当作持久命令入口。

## 事务与迁移边界

所有修改先复制、验证候选后一次性替换值对象。正式服务必须将角色版本、点数、学习、回执放入同一个 SQLite 事务，成功后才发布 ASC/UI；本阶段尚未接入这条运行时链路。局部支付 GUID 检查不替代数据库的版本绑定命令 ID 与持久去重回执。

v9 的 16 种合法四位掩码按稳定映射转为故事基础与旧快捷位置，不凭空生成点数或实付记录，不能通过重置退款。这里只转换技能子对象，整档转换仍待完整角色 DTO。

## 显式技能 DTO

ASKL 小端格式使用独立 schema 1 与内容 schema 3，保存可用点数、永久等级、故事来源、点数事件、实付记录和四个快捷位。所有键都是最长 96 字符的规范 ASCII ID；总字节上限 1 MiB，每个集合在分配前检查数量，不调用反射二进制序列化。

编码按稳定键/等级/快捷位置排序，容器插入顺序不影响字节。解码拒绝重复键、未知版本、截断、尾随数据和点数不平衡，只在全部不变量通过后替换调用方状态。装备/临时来源不在此持久 DTO 中。

UE 5.8 Editor Win64 Development 编译通过。35 项规则测试通过（报告 Rules-85aee3f5e60e4af2a61ec93a0e9a4e13），覆盖唯一来源、重复/冲突支付、无点拒绝、满级拒绝、故事基础、冷却中重置拒绝、改价后的历史退款、依赖级联、装备/临时来源、快捷位、全部 16 种旧掩码及显式 DTO 损坏拒绝。

这些结果验证规则和编码，不代表点数已经从正式玩家任务中发放，也不代表已完成数据库 Profile 切换。

# v10 完整角色 DTO 与旧角色转换

此阶段覆盖角色聚合，尚未转换整个世界档案或启用新的游戏存档后端。

## 全字段角色快照

AetherCore 的 FAetherProfileStateV10 组合固定格库存与技能 DTO，并显式保存角色键、提交版本、金币、经验、登记/伙伴状态、任务证据与已领任务、日常日期与进度、遭遇回执、待领奖励及已领奖励 ID。

APRF schema 1 使用小端格式，外层上限 4 MiB。嵌套库存上限 2 MiB，技能上限 1 MiB。字符串无损 UTF-8，数量在分配前校验；未知版本、断引用、重复领取身份、截断或尾随字节拒绝，解码失败保留旧值。存档 schema、内容 schema、网络协议和数据库版本分开管理。

角色 Revision 与数据库行版本应一致，读取服务必须核对；普通命令同时修改金币/库存/技能/任务后只生成一个候选 Profile，不能分开提交。

## v9 角色映射

只读转换器位于保留旧反射类型的 AetherLab，由显式 v9 reader 提供输入；先复验冻结旧规则再构建新值。旧反射字段及默认值保持不变。

- 原紧凑数组按顺序填入固定格，保留实例 GUID 和数量；容量不足或物品未知时失败，不截断、不删除。
- 装备槽保留对原实例 GUID 的引用；旧 FName 到新字符串 ID 只接受唯一、不区分大小写的对应。
- 四位法术映射为故事基础，不捏造技能点或购买记录。
- 原任务/日常/遭遇回执与个人状态保留。非法新引用返回诊断，不清空进度。
- PendingGold/PendingMaterial 合并为一个待领奖励，ID 从来源 SHA256 与角色键稳定生成。重复转换同一来源不会产生另一个奖励身份。
- 保留旧 Revision，记录来源 schema/SHA256/旧提交版本；旧成功回执的完整字段作为不可执行档案保存，不能转换成可重新执行的新命令。

存储导入器仍需在单个迁移事务中保留这些版本并写入整档导入标识。旧 RPC 也必须在游戏后端切换时被拒绝；只保存历史回执不等于已经完成协议切换。

## 审计入口

AuditLegacy 现在对校验通过的来源逐个转换并编码角色，报告 profilesConverted、字节数、固定容量、故事技能数量和保留版本。它仍不写数据库，finalSchemaConverted 仍为 false，因为世界、掉落、服务回执、遭遇运行和原子导入尚未完成。来源损坏或转换失败时保留原文件与诊断。

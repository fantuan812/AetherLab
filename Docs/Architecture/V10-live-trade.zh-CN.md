# v10 实际商人会话与交易界面

本单元接入当前可玩的商人 E 交互、UMG 背包面板和买卖 RPC。实际存储仍是 v9 快照服务；原生 v10 SQLite 经济处理器、完整物品实例和 CommonUI 尚未在普通游戏中切换，不能据此标记 V10-10 全部完成。

## 授权与生命周期

与商人交互后，服务器生成当前 Pawn 的临时 GUID 令牌，绑定准确 Actor、ShopId、PlayerState 实例和区分大小写的角色 ID。客户端不能通过靠近任意同类商人自行获得权限。每个新买卖请求都重新检查令牌、目标存在/启用、私有归属、250 cm 距离、遮挡以及角色是否可操作。

最近受伤或攻击/施法/眩晕结束后八秒内不开放交易；搬运、救援、旅行和未结束的动作也拒绝交易。服务器 Tick 检查有效性并关闭失效会话；失去控制、Pawn 销毁、关闭背包或切换其他菜单时清理授权。重新与商人交谈使用新令牌；旧关闭回调不能关闭新会话。同 ShopId 的邻居不能代替离开的原商人。

## 提交与恢复

持久 FAetherInventoryCommand / Receipt 保持冻结格式。ServerTradeInventory 单独携带易失授权令牌，普通无令牌入口不能提交新买卖。服务器先查询对应角色的完整旧回执，再校验新交易现场条件。已提交的相同请求即使商人已卸载，也只确认原结果，不再扣款、给物品或付款。

客户端为挂起命令保留原令牌。保存失败后“重试上次操作”沿用原命令；会话已关闭时按钮仍可用。已提交请求恢复回执，未提交且授权已失效的请求明确拒绝并清除挂起状态。没有把旧请求换成新 GUID 来规避冲突。

## 当前界面

商品列表随当前商人和会话变化刷新，不再组合所有商店。显示单价、整数数量、合价和当前拥有数；服务器再次按定义计算价格。当前旧商店按需供应，不显示虚假有限库存。

购买使用选定数量。出售前显示选中实例、数量、预计金币，第二次点击出售或按 Delete 确认；十秒超时、数量/实例/档案/会话变化会取消。不可出售、已装备和数量不足具有可见原因。关闭会话后清除旧出售确认提示。

现有面板仍是过渡 UMG；装备修理、新十槽实例信息、完整 CommonUI 导航以及新 Armorer 实体仍待后续工作，未作完整 UI 验收。

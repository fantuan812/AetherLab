# v10 规范身份与完整实例状态比较

交互测试发现 UE FString 默认相等会忽略大小写。因此不能直接把默认字符串/TMap 相等当作持久身份或完整实例元数据的精确比较。本次修复在权限和状态边界显式使用 ESearchCase::CaseSensitive：

- 完整 StackKey 精确比较定义 ID、绑定角色、StateGroup 和逐项词条键/值；Wet/wet 或 Recovery/recovery 不会合并后丢失一份状态。
- 物品实例、发放、购买、装备槽、技能效果/故事授予/快捷位/前置、角色任务引用与待领奖励物品必须引用规范定义 ID。
- 个人仓库、绑定装备/修理/使用、消耗品接收者、商人/容器现场上下文、Profile 行解码与角色会话都精确检查目标或角色身份。
- 事务 DTO 与 SQLite 提交路径均要求实际推进提交者本人的 Profile 键；效果 ActorId 也必须精确匹配。不能用 alice 行满足 Alice 的主聚合要求。
- BeginSession 保守拒绝与当前会话只差大小写的身份别名，保持原会话有效。正式认证入口仍须先解析服务器保存的规范 CharacterId，不能把客户端显示名直接当认证身份。

这不是给所有 FString 容器更换比较器，也没有迁移 SQLite 排序规则或更改旧存档反射布局。通用索引仍保守检测名字冲突；大小写别名不作为两个可互换的身份使用。不清洗或自动重写不合规范的持久数据：领域解码拒绝后保留原始来源，迁移路径负责显式规范化定义引用。

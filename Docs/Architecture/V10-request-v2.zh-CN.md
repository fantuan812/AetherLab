# 请求 v2：明确携带交互版本

v1 的原始字节布局与读取保持不变。v2 使用同样的魔数/动作编号/前部字段，在原尾部增加 8 字节小端 ExpectedInteractionRevision；-1 仍编码为全 1。22 类命令都可使用 v2，但只有 ExecuteInteraction 必须携带非负目标版本，其他动作必须为 -1。v1 不允许在内存对象中偷偷带入该字段。

范围与长度在解码时严格检查：缺少/截断/尾随字段、未知协议、整数溢出、无关动作附带目标版本都拒绝。结果格式继续独立使用 schema 2，并保留旧结果 schema 1 的读取；请求升级没有重定义结果字节。

协调者、领域候选处理器、事务 DTO 校验和 SQLite 回执查询现在显式支持请求版本 1、2。已有调用者默认仍使用 1；需要交互执行的调用者必须显式选择 2。重试必须保存原版本和原请求字节，不在重连时用新版本重新编码同一个 CommandId。持久回执同时比较 protocol 和完整 request；同 ID 改版本，即使其他业务字段相同也返回 Conflict。

交互提供者 CheckCommand 只接受 v2 ExecuteInteraction，把目标/动作/个人/世界/交互版本一并映射到 CheckSelection。旧 v1 仍能被解码以保留回执兼容，但没有独立目标版本，不能授权新的交互执行。此校验不执行副作用；真实处理器和网络入口仍待接入。

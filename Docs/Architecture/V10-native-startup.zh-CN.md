# v10 原生存储启动与恢复

2026-09-21：新增代码未编译、未测试。没有执行迁移、创建玩家数据库、打开游戏或制作资产。

## 已补代码

- SQLite InitializeWorld 只能向完全空的聚合/回执/效果库插入 Main 世界；已有世界只允许相同初始负载的幂等重试，缺世界但有其他数据时拒绝空白替换。
- SQLite CreateProfile 在同一个写事务内要求世界存在、限制至多 128 个角色、拒绝大小写别名；仅 INSERT 缺失角色，返回已有角色时不再次发放初始物品。
- FAetherWorldBootstrap 使用异步有界读取，先读取世界与角色/容器版本索引，再逐个解码所有角色和容器。检查 DTO 版本、精确身份、全库实例 GUID 唯一性、个人仓储拥有者，最后重新读取索引和世界以排除审计期间版本漂移。不会同时缓存全部角色私有负载。
- AetherNativeMigration 从 SaveGames 的两个历史代中选最高完整有效代，验证冻结 reader、CRC、SHA256 与全领域转换。不存在文件与存在但损坏严格区分；同版本不同合法内容拒绝自动决定。
- 导入前在 Saved/V10Migration 的新 GUID 目录备份同一份已校验字节和侧车，并读回比较；保存来源摘要，原文件不移动、不删除、不覆盖。备份失败不授权导入。已有原生世界优先，不重新覆盖为旧档。
- UAetherNativePersistence 提供 Prepare / 异步审计 / Prepared / Activate 生命周期：固定 Saved/V10State/<合法前缀>/state.sqlite 路径。Prepare 开始即封锁旧总写入口，失败也不回退 v9 写入。
- Activate 要求具体场景恢复、规则上下文和提交事实发布回调；恢复成功后才安装现有命令运行时。Prepared 与 Active 明确不同。
- Active 下的登录队列先读取档案，确实缺失才构建初始 2 个 Potion 候选并原子创建；返回前解码并核对身份和版本。最多 16 个并发登录，同身份加载去重；Future 完成后仍需调用者复查 Controller/会话并绑定。
- AetherNativeWorldPhysics 完成原生 DTO 与 Reactive 记录互转、已加载物理恢复、材质/机制对应校验和原动态刚体继续模拟；已声明但未加载的流送实体保留冻结。捕获只替换已加载实体与天气，不推进版本，不调用旧 SaveGame 写入。

## 尚未闭合

Prepare 仍没有普通 GameMode 的自动调用，防止在其余旧写入者未迁移时启动半套原生玩法。下一步须将 GameMode 登录/启动装配、实际 ASC/装备发布、消耗资源屏障、世界事务/区域流送、遭遇及掉落容器恢复、NPC 处理器一并接入；不能仅传永远返回 true 的回调就宣布可用。

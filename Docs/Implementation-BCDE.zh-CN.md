# B–E 实施记录 · 0.3 可玩灰盒

本轮在 UE 5.8.0 中新增“断钟修道院”可玩灰盒，保留原材料实验台。B–E 均有代码落地；下面区分已经运行验证的基础与尚未完成的生产验收。它还不是完成美术、动画和玩家测试的 15 分钟正式切片。

## 启动与控制

在工程目录的 PowerShell 中运行：

```powershell
.\Scripts\Build.ps1
.\Scripts\PlayAdventure.ps1
```

脚本使用 `/Engine/Maps/Entry?game=/Script/AetherLab.AetherAdventureMode` 启动运行时关卡。直接打开工程点击 Play 仍是原材料实验台。新关卡没有覆盖现有资产预览地图或 `test/` 工程。

| 输入 | 行为 |
|---|---|
| WASD / 鼠标 | 移动、转向、瞄准 |
| 左键 / 左 Shift | 剑轻击 / 重击 |
| 右键按住 | 举盾；最初 0.16 秒可弹反，弹反窗口有再次触发间隔 |
| 空格 | 消耗 18 体力闪避 |
| 1 / 2 / 3 / 4，然后 F | 引焰 / 引泉 / 凝霜 / 鸣雷 |
| E | 近距离交互；古印选择留在修道院 |
| Q | 古印选择带回灰渡 |
| F5 / F9 | 安全位置保存 / 读取最近手动存档 |

默认存档槽为 `AetherAdventure_v1`。运行集成测试使用独立槽 `AetherSmoke_BCDE`。尚无自动检查点；第一次进入建议在入口先按 F5。倒地后按 F9。联网模式暂不开放存档读写。

HUD 暂用英文调试字体。角色、剑盾和建筑采用基本形体，未将已有模型包宣称为完成的剑与魔法美术。

## 可验证的关卡路线

入口断桥提供三种通路：重击/加热绳索后放下木桥；冻结浅水格后走冰面；沿侧面维护道绕行。维护道不要求魔力或水量。

庭院设置连通积水、灯油和木梁，盾卫与焰术士使用同一个角色伤害入口。对电造成的环境伤害不作阵营豁免。雨与风通过环境接口影响火球，关卡默认晴天，单位测试分别验证雨中衰减与横风偏移。

修道院两侧分别是学徒和誓约记录。救援取得证词，阅读取得记录；收齐后可在骑士未蓄力时使用见证钟解誓。也可用剑与法术击败骑士，结算不要求先完成固定元素组合。

骑士解决后，救回学徒才能把古印留在修道院；没有学徒仍能选择带回灰渡。古印被毁时允许人工修桥结局。返回入口结算，重复交互不会重复发奖励。当前通过 HUD 文本记录后果，尚未制作村庄变化演出。

## 代码与状态归属

| 文件 | 职责 |
|---|---|
| `Source/AetherLab/AetherCombat.h/.cpp` | 角色、属性、GAS 施法、剑盾、服务器伤害、简易敌人、天气投射物 |
| `Source/AetherLab/AetherAdventure.h/.cpp` | 运行时布局、材料物体、Quest GameState、交互、SaveGame、HUD、集成验证 |
| `Plugins/ReactiveWorld/Source/ReactiveCore` | 焓/质量/燃烧/导电、液态转移、来源传播、批量状态恢复 |
| `Plugins/ReactiveWorld/Source/ReactiveRuntime` | UE 注册、权威检查、复制状态表现、遮挡缓存、稳定 ID 存取 |
| `Source/AetherLab/Tests/AetherTests.cpp` | 新增数值性质和规模测试 |

施法按 GAS Spec 的等级 1–4 选择预设。`CommitAbility` 调用成本校验与属性扣费；射线技能先验证目标，执行失败退回已扣魔力。引泉还扣除有限水囊库存。焰术士同样使用 GAS 激活，不能无限绕过资源。

剑伤进入角色战斗层，热/电进入反应世界再回到伤害层。温度不直接替代 HP。角色热容量代表暴露材料面片，冻结只影响移动效率，不把整个人当成瞬时冻透的冰雕。

反应携带运行时 `Source BodyId`；热传播保留本步最大供热者的来源，电和爆裂保留输入来源。这个版本是“最近显著来源”的归属政策，尚非多人助攻/长期因果账本。读档清除瞬态来源，不序列化 Actor 指针。

## 水面和守恒边界

`TransferLiquid` 从来源扣质量与液态焓，在目标增加相同数量，受来源剩余液态水、目标容量和遮挡门控限制。冻结部分不能流动。关卡目前只在作者指定的相邻格之间平衡水量，蓄水池的水通过预设渠道释放，不是任意地形流体。

水囊通过 `WithdrawLiquid` 从场景取水；库存目前只存质量，再施法时按环境水温输入，携带期间的热量交换视为环境边界。若要做保温水囊、沸水搬运或密封容器玩法，需要把库存焓也纳入材料容器。测试只声称格间转移的质量/焓守恒，不声称背包内外总热量已封闭求解。

冰面在水量至少 0.2 个模拟 kg、冰比例至少 95%、结构未破坏时开放 Pawn 碰撞。这是浅水通路的玩法代理；面积、实际冰厚与承载重量尚未建立物理对应关系。

遮挡缓存只复用同一个求解步的查询；新的步骤重新生成，避免门打开或碎块移动后长期使用陈旧连边。

## 存档与网络边界

存档包含布局版本、天气、稳定名称、材料签名、变换、焓、水量、燃料、完整度、储能、角色生命/资源与任务标记。读取先校验完整名单、数值和材料兼容性，再整体恢复数值；拒绝不兼容存档，不进行猜测迁移。尚有待处理的物理输入时不保存，避免读档丢失已提交的连锁反应。

`UReactiveBodyComponent::State` 使用 RepNotify 复制，客户端从当前基线重建相态碰撞和持续表现；客户端不运行权威反应求解器。角色属性由 GAS 复制，客户端只能请求服务器能力激活。四法术目前为 `ServerOnly`，尚未提供本地预测动画。

本地联网验证：

```powershell
.\Scripts\TestNetwork.ps1
```

脚本启动本机专用服务器，再先后启动两个客户端。第二个在第一个退出后加入，验证已冻结世界的基线；它不是两名玩家同时战斗测试。脚本只关闭自己启动的进程。
